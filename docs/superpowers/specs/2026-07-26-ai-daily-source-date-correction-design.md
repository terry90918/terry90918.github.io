# AI Daily 來源日期逐篇校正設計

## 目標

逐篇核對 2026 年 7 月 AI daily 文章實際採用的 Gmail 來源信，讓檔名、`slug` 與 `publishedAt` 的日期改為來源信日期，並補上 2026-07-22、2026-07-23 兩封尚未轉寫的內容。

## 明確範圍

- 僅處理 `content/posts/2026/ai-daily-2026-07-*.md`。
- 每次只讀取、核對、修改、驗證一篇，不使用批次改名或批次內容修改腳本。
- 不修改排程或自動化提示。
- 不保留舊 URL，也不建立 redirect。
- 不變更既有文章的事實、標題、內文與來源連結；日期校正只調整檔名、`slug` 與 `publishedAt`。
- 新補的兩篇文章須完整通過既有的獨立事實／版權審核子代理與獨立繁中潤稿子代理。

## 同日衝突

若同一來源日期產生兩篇文章，兩篇都保留日期前綴並加可辨識的主題後綴。後綴必須依文章既有主題個別決定，不使用流水號；實際後綴在讀完該篇文章與來源信後才定案。

## 單篇處理流程

1. 讀取 Gmail 原始信與待校正文章全文。
2. 用文章的公司、人名、數字及核心主題確認來源信。
3. 決定沒有衝突的新檔名與 slug。
4. 只修改該文章的檔名、`slug`、`publishedAt`。
5. 檢查 frontmatter、Markdown 載入與新 URL 生成。
6. 提交該篇文章的獨立 commit，再處理下一篇。

## 新增文章流程

對 2026-07-22 與 2026-07-23 來源信，各自：

1. 建立純文字素材。
2. 只採用可由外部來源查證的新聞事實。
3. 撰寫原創繁體中文文章。
4. 由獨立審核子代理逐項檢查版權、結構、事實及 URL。
5. 審核通過後，由另一個獨立子代理進行繁中潤稿。
6. 個別 commit。

## 驗證與發布

- 每個 commit 只包含當篇文章或該篇新增文章。
- 每次 commit 皆須通過既有 pre-commit checks。
- 全部逐篇處理完成後才 push `main`。
- GitHub Pages 完成後逐一讀回新 URL，確認 HTTP 200、標題及關鍵內文。
- 舊 URL 預期不再存在，不建立相容轉址。
