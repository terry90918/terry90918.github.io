## Codex 本機用量個案引發硬碟寫入疑慮

**事情經過：** 一篇網路報導轉述，有使用者聲稱 Codex 桌面版一個月使用約 150 GB 網路流量；這是使用者個案與網路留言，不能視為一般用量。V2EX 論壇一名 MacBook Pro 使用者表示，硬碟寫入量由 5 月 27 日的 27.7 TB 增至 6 月 21 日的 32.5 TB，約 25 天增加 4.8 TB；他稱最近一個月幾乎每天使用 Codex，不用時曾將程式留在背景，後來改成用完即退出。OpenAI Codex 的 GitHub 討論串另有一名 Mac 使用者記錄，開機後寫入量約 4.77 TB，並在 Codex 大致閒置時觀察到持續寫入。這些是不同裝置上的個別回報，並非一般使用者的平均值。[150 GB 用量報導](https://www.kucoin.com/news/flash/openai-codex-desktop-consumes-150gb-monthly-data-writes-4-8tb-to-ssd) [V2EX 使用者紀錄](https://www.v2ex.com/t/1221747) [OpenAI Codex 問題追蹤](https://github.com/openai/codex/issues/29876)

**落到現實：** OpenAI 的 Codex Cloud 文件介紹，使用者可建立或選擇一個備有程式碼儲存庫、工具與所需存取權的雲端環境，再於其中啟動任務。這說明產品提供雲端工作環境，卻不能單獨證明上述網路流量或磁碟寫入由哪個機制造成。把原因歸於常駐連線或背景索引，也需要可重現的測量才能確認。高用量個案值得產品提供清楚的資源診斷；單一使用者的紀錄不足以證明所有人都會遇到相同負擔，更不能證明公司刻意把成本轉嫁給個人裝置。[Codex Cloud 說明](https://learn.chatgpt.com/docs/cloud)

**一句話結論：** 這些紀錄提出了值得查明的資源問題；目前證據支持的是個別使用者觀察，尚不足以推論普遍用量或單一成因。

## 中國微短劇轉向 AI，工作衝擊仍需以數據衡量

**事情經過：** Caixin 報導，2026 年第一季中國上線約 12.8 萬部微短劇，其中約 12.2 萬部採用 AI 生成，占比超過 95%；報導也把變化與 ByteDance 於 2 月推出的 Seedance 2.0 等影片生成工具連結。The Next Web 估計，相關產業約有 6.6 億名使用者、規模約 165 億美元。另有一組估算稱，該產業歷經四年發展後，使用者數達 7 億，年營收達 1,000 億元人民幣；但目前可讀來源未能核實這組數字，因此不把兩組估算合併比較。[Caixin 報導](https://www.caixinglobal.com/2026-06-01/cover-story-how-ai-took-over-chinas-micro-drama-industry-in-90-days-102449814.html) [Seedance 2.0 報導](https://www.theguardian.com/film/2026/feb/13/new-ai-video-generator-seedance-tom-cruise-brad-pitt) [The Next Web 產業規模估算](https://thenextweb.com/news/china-micro-drama-ai-state-funding)

**落到現實：** Caixin 採訪中的一名製作人表示，AI 改變內容判斷流程，部分中高階人員感受到壓力；報導也提到，三個月前有動畫短劇團隊由六人組成，現在則出現由一人公司處理全流程的情況。The Next Web 則指出，重視情感細節與真人表演的類型仍往往由真人演出，AI 在某些題材更像補充。現有可讀來源沒有證實「橫店實拍量只剩前一年的 60%」，也沒有支持微短劇在 2025 年提供 130 萬個工作的精確統計，因此不把這些數字當作已核實結果。AI 作品數量占比也不等於工作機會按相同比例消失，整體影響仍須就業、收入與製作品質資料判斷。

**一句話結論：** 生成內容已快速擴大供給，但 95% 的作品占比不能直接換算成 95% 的工作流失。

## 韓國把半導體、資料中心與實體 AI 放進多年期計畫

**事情經過：** 韓國的計畫涵蓋半導體、AI 資料中心與實體 AI。Samsung 官方揭露的投資願景為 2026 至 2040 年國內投資約 2,450 兆韓元，其中約 2,100 兆韓元用於半導體；公司也明確表示，這項規劃可能隨市場與經營環境改變。SK hynix 則公布約 1,100 兆韓元的中長期投資策略。韓國政府表示，SK、GS 與 Naver 等企業將投入約 550 兆韓元，建置初期總容量 8.4 GW 的 AI 資料中心；Reuters 報導，首階段工程目標於 2028 年上半年啟動，相關投資到 2035 年前後可能超過 1,000 兆韓元。[Samsung 投資揭露](https://www.samsung.com/sec/ir/reports-disclosures/public-disclosure/3996/) [SK hynix 投資策略](https://news.skhynix.com/en/fact-05/) [韓國政府資料中心計畫](https://www.msit.go.kr/eng/bbs/view.do?bbsSeqNo=42&mId=4&mPid=2&nttSeqNo=1284&sCode=eng) [Reuters 韓國三大 AI 計畫整理](https://finance.yahoo.com/technology/ai/articles/factbox-key-facts-south-koreas-102928379.html)

**落到現實：** 韓國政府也把實體 AI 列為發展方向，目標在 2030 年前成為全球領先國家；Reuters 報導，政府計畫於 2028 年推動十個主要產業的人形機器人商用化。政府表示會協調土地、電力和許可程序，以支援私人資料中心投資。這些都是跨越多年的規劃和目標，公告金額與容量不等於已完成的支出或已建成的設施。[韓國政府資料中心計畫](https://www.msit.go.kr/eng/bbs/view.do?bbsSeqNo=42&mId=4&mPid=2&nttSeqNo=1284&sCode=eng) [Reuters 韓國三大 AI 計畫整理](https://finance.yahoo.com/technology/ai/articles/factbox-key-facts-south-koreas-102928379.html)

**一句話結論：** 韓國提出的是跨越多年、包含私人投資與政策目標的產業計畫；公告金額不等於已完成的支出或保證實現的容量。

## Claude Code 的使用者檢查機制引發隱私疑問

**事情經過：** Anthropic 表示已發現多家 AI 實驗室透過大量帳號蒐集 Claude 輸出，進行未授權的模型蒸餾。Reddit 貼文作者和 TechStartups 後續報導則稱，相關檢查只在使用代理或自訂 `ANTHROPIC_BASE_URL` 端點時啟動：Claude Code 會讀取作業系統時區，比對代理網址是否屬於特定中國網域或 AI 實驗室，再透過 system prompt 的日期格式與標點差異編碼線索。這些說法來自第三方程式碼分析，描述的是特定設定下的觀察，並非 Anthropic 已確認的產品行為。[Anthropic 的蒸餾防範說明](https://www.anthropic.com/news/detecting-and-preventing-distillation-attacks) [Reddit 程式碼分析](https://www.reddit.com/r/ClaudeAI/comments/1ujila1/anthropic_embedded_spyware_in_claude_code_and/) [相關技術分析](https://techstartups.com/2026/06/30/anthropics-claude-code-accused-of-hiding-proxy-fingerprints-inside-system-prompts-to-identify-china-linked-users/)

**落到現實：** 這項分析引出一個具體問題：開發工具讀取環境設定並傳回分類訊號時，使用者是否知道檢查的範圍、目的與後續處理方式？目前資料不足以證明所有 Claude 使用者都被追蹤，或證實 Anthropic 的設計意圖。

**一句話結論：** 反蒸餾措施與使用者監測不是同一件事；要討論信任，必須把觀察到的程式行為、公司說法與外界推論分開。
