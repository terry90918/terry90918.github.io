> CrowdStrike 追查 9 月底至 10 月初的南韓金融機構資料外洩活動，在攻擊者控制的目錄找到 Claude Code 工作階段、ARTEX 設定與記憶檔。報告說明了工具鏈，但未確認受影響機構總數。

CrowdStrike Intelligence 指出，一場針對南韓金融機構的活動在 2026 年 9 月底至 10 月初進行，並造成資料外洩。研究團隊在攻擊者控制的公開目錄找到 Claude Code 工作階段紀錄、ARTEX 設定檔與 Claude 記憶檔。[CrowdStrike 的分析](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)以這些檔案還原操作者使用的工具與操作方式。

把事件簡化成「AI 自己駭進銀行」超出這份報告能支持的範圍。CrowdStrike 公開的線索是攻擊者端的工作階段與設定檔；它們能顯示工具如何被配置，不能單獨證明模型自行選擇目標或完成整場入侵。

![剪紙伺服器和開啟資料夾位於金融街前方。](/images/ai-daily/2026-10-09/01-hero.webp)

## 公開目錄留下工具痕跡

CrowdStrike 將這次活動描述為攻擊者使用 ARTEX 與大型語言模型。研究團隊在一台伺服器的公開目錄找到 Claude Code 的設定檔，其中包含中文的滲透測試提示；另一個由攻擊者控制的香港 IP 也出現在文件裡。[報告列出的伺服器與目錄線索](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)讓研究者得以查看部分工作階段紀錄和工具設定。

## 兩台伺服器各有角色

![俯視的兩組剪紙伺服器由赭色紙路連到中央資料夾。](/images/ai-daily/2026-10-09/02-concept.webp)

CrowdStrike 從 Claude Code 工作階段推斷，香港 IP 是主要攻擊端基礎設施；`38.244.50.120` 則架設 ARTEX 執行個體，可能負責報告所述的韓國攻擊。原文使用「likely」描述這個關聯，並沒有把伺服器與每次入侵都定為確證關係。[CrowdStrike 的基礎設施分析](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)也指出，兩邊的開放目錄留下不同類型的設定與紀錄。

ARTEX 是一款中國開發的開源代理式滲透測試工具。報告中的 ARTEX 執行個體以 DeepSeek V4.1 Flash 作為主要模型後端；其他 Claude Code 工作階段則出現 GLM-5.3 與 Grok 4.6。[CrowdStrike 對工具與模型的說明](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)把滲透測試工具、模型後端與程式工作階段分開描述，不能把它們統稱為單一的「AI」角色。

## 受影響範圍仍未確認

![斜角紙製資料夾和伺服器位於金融機構剪影之前。](/images/ai-daily/2026-10-09/03-impact.webp)

CrowdStrike 表示，這場活動涉及南韓金融機構並造成資料外洩，但在報告發布時，受影響機構數仍未確認。原文也把部分銀行系統遭入侵的細節標為來自產業報導。[報告中的範圍註記](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)提醒，讀這份報告時應把產業報導提供的銀行系統背景，和 CrowdStrike 自行分析出的基礎設施線索分開看。

這次調查能確認的是一段工具鏈：攻擊者使用 ARTEX 與模型，並留下可被研究者讀取的設定和工作階段紀錄。公開資料尚未證明模型自行決策或單獨執行攻擊；把工具使用與自主行動分開，才能看清這份威脅分析實際支持到哪裡。
